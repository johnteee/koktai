# 方法論備忘（可複用的做法與原則）

本專案（格式復原＋跨語料 join）沉澱下來的工作方法，供後續卷次、其他韻書資料集重用。

## 1. 無損轉換原則

1. **每層留 raw**：解析輸出旁掛原始行；造字以 `&#xfXXXX;` ASCII 逃逸——
   既可逆，又不會被管線後段的文字替換誤傷。
2. **解不了 ≠ 丟**：失敗片段進 `unparsed`/`stray`/`annotation_notes`/`errors`
   結構欄位；stdout 永遠只有合法 JSON，診斷走 stderr。
3. **相容欄位照舊、保真欄位另立**：v1 消費者不破（`pronun_*`），
   新資訊加欄（`sentence_ruby`、`tokens`）而非改語意。
4. **標記語意先考古再移植**：`jade-unescape.pl` 的 Fc 區「裸放」語意藏在
   一個 regex 分支裡；重寫前逐分支對照，否則「卡癶襠→卡襠」這類靜默損失
   要靠 parity 差集才抓得到。

## 2. 對等驗證（parity gate）

改寫轉換器時，以舊輸出為金標做**多重集差集**，而非抽樣目測：

- 計數層：條目數逐卷對帳（2,200 vs 2,200）。
- 名稱層：entry 名稱 multiset 雙向差集歸零（記法差異先正規化，
  如 `<glyph:k/xxxx>` ≅ `<mark>&#xfxxxx;</mark>`）。
- 內容層：關鍵欄位（`pronun_bopo`）逐句比對；殘差逐筆歸因
  （14 筆 = 台/國語句切分邊界，非資料損失）。

差集不為零時：先問「哪邊對」，再問「差多少」——v1 也會錯（ㆲ→onn 級的表格 bug
就是這樣浮出）。

## 3. 假說驅動的跨語料 join

對「X切，Y韻」這類半結構引文：

1. **先量測再設計**：全量抽取 → 對候選表跑精確 join → 看殘差分桶。
2. **殘差找系統性**：韻目不合桶的樣本（黠↔鎋、歌↔戈…）指向平水併部；
   「僅正韻」韻目全是異體字假象（真/眞）——**字形正規化表要用目標資料集
   的實際拼寫來核**（ytenx 用眞晧号寑豔釅）。
3. **寬鬆規則要具名**：每條放寬（同平水部、正韻唯一）都寫進 `method` 欄，
   下游可按嚴格度過濾；絕不無聲降級。
4. **多鍵 fallback**：反切字串 join 44%→58%，字頭字級 join 86%——
   粒度粗但穩健的鍵作後盾，並揭露歧義（候選列表＋上限）。
5. **殘差誠實掛起**：4,661 筆集韻反切在 ytenx 域內無解就標 no-join，
   不硬塞；缺口寫進文件（補集韻資料集是正解）。

## 4. 先驗表 vs 實測資料

- 平水↔台羅、206↔106 是**先驗知識層**：從文獻（PDF/標準韻書學）編定，
  `_meta` 記出處；不用索引輸出反向修表（防循環論證）。
- 先驗表的用途是**一致性檢核**與檢索軸，不是改寫實測讀音的依據；
  「食：職韻預期 ik、實讀 sit8」這類衝突是資訊，不是錯誤。

## 5. 除錯教訓（本專案實例）

| 症狀 | 根因 | 通則 |
|---|---|---|
| 全部 ong 變 onn、裸 ㄨ 變 uh | Python dict 重複鍵靜默覆蓋＋反轉表 | 生成反查表前先 assert 鍵值雙向唯一；重複鍵是資料 bug 不是風格問題 |
| 13k 行「找不到韻母」警告 | 第 8 調 `◌ ͘`（U+0358＋前置空白）不在調表；國語注音混入 | 警告洪流＝分類缺失的訊號；先 `uniq -c` 分佈再修，不逐筆滅火 |
| 單字數 600→1200 幽靈 | `.本文` 成對出現＋空白行也算內容 | 條目成立條件用「有意義欄位」而非「有任何行」 |
| 卷 3 反切 7 筆 | 排版變體（段碼無 bb1、尾碼不同） | 對「異常低」的卷別統計立刻抽原文比對，不要平均值掩蓋 |
| JSON 被 `unanalyzed` 汙染 | 診斷印到 stdout | stdout 是資料通道，診斷一律 stderr |

## 6. 產出物自述

每個生成檔（JSON 索引、資料表）內建 `_meta`：generator、來源、統計、日期。
文件（docs/）記「為什麼」；`_meta` 記「是什麼、哪來的」——兩者互補，
避免產出物脫離文件後失去出處。
